## 适用场景 / 触发条件

**适用范围**：将单篇或多篇微信公众号文章获取并整理为独立项目。

**触发条件**：
- 用户提供了微信公众号文章链接（`https://mp.weixin.qq.com/s/...`）
- 用户需要保存文章内容（含图片）到本地
- 用户需要对文章进行结构化整理

**不适用 / 中断条件**：
- 文章需要登录才能查看（中断，提示用户）
- 文章已被删除或链接失效（中断，提示用户）

## 目标与质量标准

**目标**：完整获取公众号文章内容（文字 + 图片），并整理为结构化项目目录。

**验收标准**：
- ✅ 文章文字内容完整提取（无遗漏）
- ✅ 文章配图全部下载到本地（images/ 目录）
- ✅ 文章内容.md 包含完整文章信息和内容
- ✅ 图片已插入到文章对应位置
- ✅ 图片内容总结已补充

**质量等级**：
- 🟢 **优秀**：文字完整、图片完整、文章内容.md 格式美观、图片总结到位
- 🟡 **合格**：文字完整、图片完整、文章内容.md 基本可读
- 🔴 **不合格**：文字缺失、图片缺失、文件结构混乱

## 输入清单

**必需输入**：
- 微信公众号文章链接（`https://mp.weixin.qq.com/s/...`）

**可选输入**：
- 图片内容描述（用户补充，用于更新 文章内容.md 中的图片总结）

**输入缺失时的降级策略**：
- 无文章链接 → 中断，提示用户提供链接

## 约束条件

**硬约束**：
- 必须使用浏览器自动化工具（playwright-cli）获取内容（web_fetch 无法获取图片）
- 图片必须下载到本地 `images/` 目录，不能只保存链接

**软约束 / 偏好**：
- 文章内容.md 只保留文章内容和图片（给人看），技术手段放 context.md 或 process_insight.md
- 封面图不获取，也不插入到 文章内容.md 中

**冲突处理规则**：
- 如果文章文字和图片冲突（例如图片无法下载），优先保证文字内容完整，图片用截图替代

### 步骤总览

2. **使用浏览器自动化** — 用 `playwright-cli` 打开文章页面，获取完整内容（含图片）
3. **下载图片** — 提取页面中所有图片 URL，用 `curl` 下载到本地
4. **⚠️ 自动创建项目目录** — 在 `1_未学习文章/` 下创建新项目目录，按 `{公众号}_{发布时间}_{文章名}` 命名
   - **必须在获取内容后立即执行，不等待用户提醒**
5. **⚠️ 自动整理文件** — 将图片、截图、数据文件移动到项目目录的对应子目录
6. **⚠️ 自动生成 文章内容.md** — 只保留文章内容和图片（给人看），立即保存到新建的目录中
   - **必须在创建目录后立即执行，不等待用户提醒**
7. **更新 context.md 或 process_insight.md** — 记录技术手段和采集说明
8. **询问图片内容** — 请用户描述图片内容，补充到 文章内容.md 中

**自动化检查清单**：
- ✅ 每获取一篇文章后，立即创建目录并保存 `文章内容.md`
- ✅ 不要在获取所有文章后才批量创建目录（除非用户明确要求）
- ✅ 如果文章获取失败或不完整，也要创建目录并保存已获取的内容
- ✅ 创建目录和保存文档是强制步骤，不是可选项

## 整理学习内容工作流

### 触发条件
用户说"整理学习内容"时启动。

### 输入
- `3_学习输出/学习.txt`：用户的学习笔记

### 学习.txt 格式说明
每篇文章以一个微信链接行开头，后跟若干行感悟/摘录，最后可能有一行题材&标的信息：
```
https://mp.weixin.qq.com/s/xxxxx
感悟/摘录内容（可能多行）
题材标签（如"设备+测试"）或 【标的】题材名：标的1、标的2、标的3
```
- 链接行：以 `https://mp.weixin.qq.com/s/` 开头
- 感悟/摘录行：链接之后、下一个链接或文件末尾之间的非空行
- **题材&标的识别规则**：只有行首标明"标的"的行（如 `【标的】` 开头）才被视为正式题材&标的，需要更新到标的文件。不以"标的"开头的题材标签（如"设备+测试"）仅为用户备注，不触发标的更新

### 执行步骤

1. **读取学习.txt** — 解析所有文章条目（链接、感悟/摘录、题材&标的）
2. **逐篇获取文章** — 对每个链接，按已有文章采集流程（web_fetch + playwright-cli）获取文章内容，保存到 `2_已学习文章/{公众号}_{日期}_{标题}/`，结构与现有文章一致（`data/`、`images/`、`screenshots/`、`文章内容.md`）
3. **生成待审阅文件** — 创建 `3_学习输出/学习_{当天日期}_待审阅.txt`：
   - 文件开头记录学习时间区间：`学习时间区间：{最早文章日期} ~ {最晚文章日期}`
   - 然后按文章组织感悟/摘录内容
4. **更新标的文件** — 仅处理行首标明"标的"的行（如 `【标的】` 开头），将题材&标的更新到 `2_projects/中长线逻辑识别/interest_stock.md`：
   - 题材以一级标题（`#`）形式存在，标的每行一个
   - **智能匹配**：先理解用户标的的题材含义，尽量归入文件中已有的题材名（如"铜箔"→`# PCB`，"液冷"→`# 液冷`），实在无对应题材才新增
   - 如果题材已存在：在下面追加新标的（同一题材下标的去重）
   - 如果题材不存在且无已有题材可归：新增一级标题，追加标的
   - 写入格式：`标的名称（异动原因）` 或纯标的名称，使用中文括号
   - **标的名称验证**：更新前必须通过 web_search 查询股票代码验证标的名称是否正确，避免错别字
   - **格式规范**：每个 `# 题材` 标题上方必须留一个空行（文件首行除外），标题后紧跟股票列表，段落内不允许出现空行
5. **不清空学习.txt** — 保留用户原始笔记，不做任何修改

### 待审阅文件格式
```markdown
学习时间区间：2026-05-14 ~ 2026-05-15

---
【文章1标题】
链接：https://mp.weixin.qq.com/s/xxxxx

感悟/摘录内容...

---
【文章2标题】
链接：https://mp.weixin.qq.com/s/yyyyy

感悟/摘录内容...
```

### 与中长线逻辑识别项目的联动
- 标的文件路径：`2_projects/中长线逻辑识别/interest_stock.md`
- 该文件为题材&标的信息的唯一数据源，所有项目（公众号文章梳理、涨停板复盘）统一写入此文件
- 更新时严格去重：同一题材下，已存在的标的不重复添加
- 写入格式：`标的名称（异动原因）`，使用中文括号
- **题材归并**：优先理解语义将标的归入已有题材（如液冷→`# 液冷`，铜箔→`# PCB`），仅当确实无匹配时才新增题材
- 多题材时标注主/次要，与涨停板复盘项目的联动规则保持一致

## 失败模式

### 模式1：文章链接失效
- **触发条件**：`web_fetch` 或 `playwright-cli open` 返回 404 或超时
- **处置策略**：halt（中断并提示用户）

### 模式2：图片下载失败
- **触发条件**：图片 URL 有防盗链，无法用 `curl` 下载
- **处置策略**：use_default（使用截图替代，文章中标注）

### 模式3：需要登录才能查看文章
- **触发条件**：`playwright-cli` 打开后显示登录/关注提示
- **处置策略**：halt（中断并提示用户）

## 技术说明

### 使用的工具
- **web_fetch**：快速获取文字内容、验证链接（第一道防线）
- **playwright-cli**：浏览器自动化（获取图片 URL 和完整 DOM）
- **curl**：下载图片到本地
- **Node.js**：v18+（playwright-cli 依赖）

### 采集流程
1. `web_fetch` → 验证链接 + 获取文字
2. `playwright-cli open` → 打开文章页面
3. `playwright-cli run-code` → 执行 JS 提取图片 URL（同时检查 `src` 和 `data-src`）
4. `curl` → 下载图片（注意 `wx_fmt` 参数确定扩展名）
5. 生成 文章内容.md → 标题以 `#activity-name` 为准
6. `playwright-cli close` → 关闭浏览器

### 技术要点
- ✅ 成功绕过微信公众号的反爬虫机制
- ✅ 图片扩展名通过 URL 中 `wx_fmt` 参数确定
- ⚠️ 封面图不获取
