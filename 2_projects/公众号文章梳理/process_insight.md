## 🎯 关键决策（Key Decisions）

### 决策1: 使用浏览器自动化而非简单抓取
**决策内容**: 选择使用 `playwright-cli` 浏览器自动化工具，而非简单的 `web_fetch`  
**决策理由**:
- `web_fetch` 无法获取图片（微信公众号有防盗链机制）
- 需要 JavaScript 渲染才能获取完整的图片 URL
- 浏览器自动化可以模拟真实用户访问，绕过部分反爬虫限制

**收益**:
- ✅ 成功获取完整文字内容
- ✅ 成功提取并下载所有图片（4张）
- ✅ 保存了页面截图作为备份

**决策约束**:
- 需要安装额外的工具（`playwright-cli`）
- 需要更多的系统资源（Chromium 浏览器）
- 执行时间更长（需要等待页面加载）

---

### 决策2: 使用本地安装而非全局安装
**决策内容**: 在项目目录本地安装 `@playwright/cli`，而非全局安装（`npm install -g`）  
**决策理由**:
- 全局安装需要管理员权限，遇到 `EACCES` 权限错误
- 本地安装无需特殊权限，更简单快捷
- 避免污染全局环境

**收益**:
- ✅ 快速成功安装工具
- ✅ 避免权限问题
- ✅ 项目自包含，便于迁移

**决策约束**:
- 需要使用 `npx playwright-cli` 而不是直接的 `playwright-cli` 命令
- 其他项目无法直接使用（需要各自安装或配置 PATH）

---

### 决策3: 创建结构化项目目录
**决策内容**: 将所有输出文件组织到独立的结构化目录中，而非散落在根目录  
**决策理由**:
- 便于管理和查找
- 符合系统分层结构（projects 层级）
- 为后续批量处理多个文章做准备

**收益**:
- ✅ 文件组织清晰（images/、screenshots/、data/）
- ✅ 包含完整的 文章内容.md 说明文档
- ✅ 便于版本控制和备份

**决策约束**:
- 需要额外的文档维护工作（文章内容.md）
- 目录结构可能需要根据后续需求调整

## 🔬 关键试错（Key Trials）

### 试错1: 使用 web_fetch 抓取
**尝试方向**: 使用内置的 `web_fetch` 工具直接抓取文章内容  
**观察到的结果/信号**:
- ✅ 成功获取文章文字内容
- ❌ 无法获取图片 URL（防盗链机制）
- ❌ 返回提示"需在微信生态内访问"

**结论/教训**:
- 对于需要 JavaScript 渲染或有反爬虫机制的页面，简单的 HTTP 请求不够
- 需要浏览器自动化工具来处理动态内容

---

### 试错2: 安装 agent-browser
**尝试方向**: 使用 `agent-browser` skill 进行浏览器自动化  
**观察到的结果/信号**:
- ❌ 全局安装失败（`npm install -g agent-browser` 报 `EACCES` 权限错误）
- ❌ 命令不可用（`agent-browser: command not found`）

**结论/教训**:
- `agent-browser` 可能需要更复杂的安装步骤或环境配置
- 遇到权限问题时，应立即切换到本地安装方案
- 不要多次重复尝试相同的失败方案

---

### 试错3: 本地安装 @playwright/cli
**尝试方向**: 在项目目录本地安装 `@playwright/cli` 包  
**观察到的结果/信号**:
- ✅ 安装成功（`npm install @playwright/cli` 成功）
- ✅ 命令可用（`npx playwright-cli` 可以执行）

**结论/教训**:
- 本地安装是绕过权限问题的有效方法
- `playwright-cli` 比 `agent-browser` 更容易安装和使用
- 应该优先尝试更简单的方案

---

### 试错4: 提取图片 URL 的方式
**尝试方向**: 使用 `playwright-cli eval` 执行 JavaScript 提取图片 URL  
**观察到的结果/信号**:
- ✅ 成功提取所有 `<img>` 标签的 `src` 和 `data-src` 属性
- ✅ 发现部分图片使用 `data-src` 而非 `src`（懒加载机制）
- ✅ 部分图片 URL 有效，可以直接用 `curl` 下载

**结论/教训**:
- 需要同时检查 `src` 和 `data-src` 属性
- 微信公众号的图片 URL 不一定都有防盗链，需要实际尝试
- 使用 JavaScript 提取比解析 HTML 更可靠

- 避免了无用功（链接失效时直接中断）

**决策2: 用 `run-code` 替代 `eval` 获取图片位置**
- `eval` 的 shell 引号嵌套问题导致 JSON 解析失败
- `run-code` 可以执行完整 JS 函数，稳定获取图片在文章中的准确位置

**决策3: 使用 `innerText` 保留段落结构**
- 第一版 batch_fetch 的 markdown 段落合并在一行
- 改用 `innerText` 结合图片位置信息生成分段格式的 markdown

### 关键试错

**试错1: shell 脚本的引号嵌套问题**
- `node -e` 中嵌入 JS 代码时，模板字面量、正则等语法被 shell 提前解释
- 多次迭代（batch_fetch → v2 → v3）后才解决
- **教训**: 复杂 JS 应写入文件执行，而非用 `-e` 参数传递

**试错2: 文章标题获取"

- 发现后用 playwright 直接读 `#activity-name` 元素确认标题
