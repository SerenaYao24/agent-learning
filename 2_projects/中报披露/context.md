# 中报披露 · 业绩预告查询

## 项目类型（which workflow）

cninfo-yjyg-query — 查询巨潮资讯网 A 股半年度/季度业绩预告，解析 PDF 提取财务数据，按主题分类增量入库。

## 适用场景/触发条件（When to use）

**适用范围**：A 股上市公司半年度业绩预告、季度业绩预告的数据查询与整理。

**触发条件**：
- 每日运行 `daily_run.py` 后提示有新公告
- 手动发起 "查询业绩预告/中报披露/季度业绩预告"
- 需要批量查询关注标的（`interest_stock.md`）的业绩预告情况
- 看板数据需要更新或修复

**不适用/中断条件**：
- 巨潮资讯网搜索接口不可达或返回错误 — 改用 `web_fetch` 兜底
- 下载的 PDF 文本提取为空 — 标记为"文本提取失败"并跳过
- CSV 解析发现行数与预期不符 — 检查 CSV 引号转义正确性（见失败模式）

## 目标与质量标准（What good looks like）

**目标**：准确、完整地获取已发布业绩预告的财务数据，按主题分类展示在看板中。

**验收标准**：
1. 所有已发布的业绩预告公告均被搜索到（巨潮搜索结果列表全覆盖）
2. 每只股票的数据列完整：业绩类型、同比/环比、上年同期、**主营业务、原因、舆论**，且主营业务≠原因
3. CSV 文件可被浏览器端 JS 正确解析，行数与预期一致
4. 看板各主题 tab 中股票数量加总等于总入库数
5. "最新披露"标记只在最新批次有效，旧批次标记已清除
6. 舆论列信息均标注来源日期，无法验证的信息不写入
7. **主营业务列不包含"增长""提升""受益"等变动描述词**

**质量等级/降级口径**：
- 若巨潮搜索接口返回为空，但通过 `web_fetch` 或 `web_search` 获取到公告列表，视为降级可接受
- 若某个股 PDF 文本提取失败，跳过该股，在 CSV 末尾标记 `# SKIP: {原因}`，不影响其他股入库

## 输入清单（Input）

**必需输入**：
- 巨潮资讯网搜索接口（搜索关键词如 "2026年半年度业绩预告"）
- 各股对应的 PDF 公告文本
- `2_projects/中报披露/数据.csv` — 已有数据的 CSV，用于去重

**可选输入**：
- `interest_stock.md` — 关注标的自选股列表，用于定向查询
- `信息汇总.md` — 现有人工校验的数据摘要
- `index.html` — 看板前端，用于验证渲染正确性

**输入缺失时的降级策略**：
- 巨潮搜索接口不可用 → 改用 `web_fetch` 工具（参见失败模式"来源不可达"）
- CSV 不存在（首次运行） → 空文件创建，后续增量写入
- 新公告 PDF 文本提取为空 → 标记跳过（参见失败模式"PDF 提取失败"）

## 约束条件（Constraints）

**硬约束**：
- CSV 必须严格遵循标准 CSV 格式：引号内的逗号不视为字段分隔符；含逗号/换行的字段须用双引号包裹；字段内的双引号须转义为两个双引号
- 搜索关键词必须精确匹配巨潮资讯网的公告标题格式
- 入库前必须查重（股票代码 + 业绩期间）

**软约束/偏好**：
- 按个股市值从大到小排序插入
- 新数据标记"最新披露"前清空所有旧标记
- 舆论信息优先使用同花顺F10、东方财富F10等主流平台数据

**冲突处理规则**：
数据完整性优先于格式美观。若 CSV 数据正确但看板显示异常，优先诊断 CSV 格式问题。

## 工作指令（Workflow instructions）

**开始指令**：
加载 `cninfo-yjyg-query` 技能，读取 `2_projects/中报披露/信息汇总.md` 和 `数据.csv` 获取现有数据。

**步骤总览**：
1. **查重** — 读取 `数据.csv` 提取已有股票代码
2. **搜索** — 调用巨潮搜索或 `fetch_cninfo_announcements.py` 获取新公告，传入 `--exclude` 跳过已有代码
3. **解析** — 提取 PDF 中的财务数据：业绩类型、同比、上年同期、**主营业务（简洁描述，非原因）**、业绩变动原因
4. **查 Q1 + 算环比** — 搜索各股一季报数据，计算 Q2 环比
5. **主题分类** — 按业绩变动原因的最大因子归类
6. **搜集舆论** — Cross Check 一致预期等舆论信息
7. **增量更新** — 写入 `信息汇总.md` 和 `数据.csv`
8. **校验并启动看板** — 验证 CSV 解析正确后启动/重启 HTTP 服务

**每步产出/检查点**：
- 步骤 1-2：产出新公告 JSON 数组（空数组则结束）
- 步骤 3-6：产出每只股票的完整结构化数据，**确认主营业务列≠原因列**（主营业务不含"增长""提升""受益"等词）
- 步骤 7：更新 `数据.csv` 后，**必须用对应解析器验证行数一致**（node 或浏览器），**同时扫描主营业务列是否混入原因词**
- 步骤 8：看板各 tab 计数加总 = 入库总数

**停止与重跑条件**：
- 新公告数组为空 → 正常停止
- 日终完成所有分类写入 → 正常停止
- CSV 引号错误导致行吞没 → 修复 CSV 后重启服务、硬刷新浏览器重试

## 失败模式（Failure modes）

### FM-1：CSV 引号转义错误导致行被吞没

- **触发条件**：CSV 行中引号未正确转义/闭合
- **模式类型**：阻断型 blocking
- **严重程度**：高 high
- **失败表现**：浏览器端 CSV 解析器因 `inQuote` 状态错乱，将后续多行合并为一行，大量数据丢失。例如宁波华翔行末尾 `",","` 多了一个引号，导致其后 4 行数据被吞没。
- **征兆**：看板某 tab 中股票数量显著少于预期；其他产业链 tab 显示 4 条而非 8 条
- **影响范围**：丢失数据的股票不会在任意 tab 显示，导致用户误以为数据未入库
- **判定依据**：用 `node` 或 `curl` 验证 CSV 行数是否匹配；检查末尾字段是否包含非法引号
- **处置策略**：`rerun` — 找到非法引号位置并修复，确认修复后重启 HTTP 服务，用户硬刷新浏览器
- **质量验收口径**：修复后看板显示行数与 CSV 数据行数一致

### FM-2：巨潮搜索接口返回 404/超时

- **触发条件**：Python 3.8 的 `urllib` 向巨潮 POST 请求时返回 HTTP 404
- **模式类型**：降级型 degradation
- **严重程度**：中 medium
- **失败表现**：`fetch_cninfo_announcements.py` 报错退出
- **征兆**：脚本 stderr 输出 HTTP Error 404
- **判定依据**：确认是网络/SSL 问题还是搜索词问题
- **处置策略**：`use_default` — 改用 `web_fetch` 或 `web_search` 工具手动获取公告列表
- **默认值策略**：`web_search` 搜索"2026年半年度业绩预告 巨潮资讯网"获取结果，来源标注为"web_search 替代"

### FM-3：主营业务列被填入业绩变动原因

- **触发条件**：从PDF提取数据时，未区分"公司主营业务"和"业绩变动原因说明"两个字段
- **模式类型**：阻断型 blocking
- **严重程度**：高 high
- **失败表现**：表格"主营业务"列显示的是业绩变动原因（如"受益于下游需求增长..."）而非业务描述（如"光纤光缆、汽车线束"）；"原因"列被挤占为舆论内容
- **征兆**：看板中某股票主营业务显示为公司简介或大段变动描述，而非简洁业务标签
- **判定依据**：检查"主营业务"列是否包含"增长""提升""受益""增加""持续"等变动/动态描述词。若有则说明混淆了
- **处置策略**：`rerun` — 找到该行，将主营业务修正为简洁业务描述，原因列填入正确的变动原因，舆论列填入机构预期数据
- **质量验收口径**：主营业务列不含变动描述词，与原因列内容不重叠

## 复用方式（Reuse）

**复用边界**：
- 整个 workflow 可直接运用于每年的半年报/季报业绩预告查询，修改搜索关键词中的年份即可
- 舆论收集流程（web_search Cross Check）可独立抽取用于其他财报分析场景

**参数化点**：
- 搜索关键词中的年份/期间（如 `2026年半年度` → `2027年半年度`）
- `--exclude` 股票代码列表

**版本/兼容性口径**：
- 每年新期间的数据插入不影响旧数据
- 修改 CSV 格式（如增减列）需同步更新 `index.html` 的解析逻辑和表头

## 证据/示例（Examples）

**正例**：
- 2026-06-15 至 2026-06-30 成功入库 15 只股票（长川科技、亿纬锂能、立讯精密等），归类至 AI 硬件、新能源、其他产业链三个主题，看板正常运行。

**反例（失败模式触发）**：
- 2026-06-30：宁波华翔（002048）的 CSV 行末尾 `...承压","` 多了一个引号，导致 `inQuote` 状态错乱，后续百润股份、盛达资源、银禧科技、圣元环保 4 条数据被吞没。看板"其他产业链"tab 只显示 4 条而非 8 条。修复方法：将 `","` 修正为 `,,"` 后重启服务。
