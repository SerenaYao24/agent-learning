1. Usable output（可用的输出）
目标：输出要清晰到"能直接用"，包括：观点/备忘、写明判断依据与维度、以及下一步要做什么。
2. Quality diagnosis（质量诊断）
目标：把诊断拆开看清：上下文是什么、工作模式是什么、提示词是什么、需要哪些工具/访问权限、以及模型限制是什么。
3. Full-task delegation（把完整任务委派出去）
目标：用一句话把任务委派出去，让"流程"自动跑：检索、执行、检查、再回报结果（变成流水线/代理式工作）。
4. Compounding memory（复利式记忆）
目标：个人和团队积累上下文与经验，让新任务不必重复过去的判断与纠错逻辑。
5. New capability（新能力）
目标：AI能捕捉"漏掉的动作"、持续监控偏移与漂移（drift），并创建后续跟进/子流程系统。
6. Quality / QA gate（质量验收关卡）
目标：所有功能变更必须通过语法校验 + 用例验证，不留手尾。
规则：
- 不同代码使用各自的语法校验工具：
  - JavaScript/HTML → `node --check <script>块提取文件`
  - Python → `python3 -m py_compile` 或 `python3 -c "ast.parse(open(f).read())"`
  - 其他 → 对应语言的标准 lint/check 工具
- 用例测试（涉及图形界面的用 Playwright 测试，CLI/API 的用脚本断言）：
  - 验证核心功能路径
  - 确保无 console error / page error（前端）
- **语法校验不通过 / 用例测试失败 → 不停止修复，继续排查直到全部绿灯**
- 首次修复后必须执行上述验证，确认通过才算"修复完成"
